# build.rs の堅牢性を改善する（タイムアウト、SHA256 検証、リトライ）

- Priority: High
- Created: 2026-06-06
- Model: DeepSeek V4 Pro
- Branch: feature/fix-build-rs-robustness
- Polished: 2026-06-06
- Completed: 2026-06-07

## 目的

`build.rs` の prebuilt ダウンロード処理の堅牢性を以下の観点で改善する:

1. curl に `--connect-timeout` と `--max-time` を追加し、ネットワーク不調時の無限ハングを防ぐ
2. SHA256 ハッシュ比較に定数時間比較を使用する
3. SHA256 チェックサムファイルのフォーマット検証（64 文字の 16 進数であること）を追加する
4. curl と git clone にリトライロジックを追加する
5. curl ダウンロード失敗時のエラーメッセージに HTTP ステータスコードを含める

## 優先度根拠

- ネットワーク不調でビルドが無限ハングする可能性（タイムアウトなし）
- タイミング攻撃で SHA256 ハッシュが推測可能（定数時間比較なし）
- 破損したチェックサムファイルでの誤検証リスク（フォーマット検証なし）
- 一時的なネットワークエラーでビルド全体が失敗する（リトライなし）

## 現状

| 問題 | 対象行 | 現状 |
|---|---|---|
| タイムアウトなし | `build.rs:179-184`, `:190-194` | `curl -fsSL -o <file> <url>` |
| 定数時間比較なし | `build.rs:244` | `if actual != expected` |
| フォーマット検証なし | `build.rs:236-241` | 空白区切りの先頭トークンを無検証で使用 |
| エラーメッセージ不足 | `build.rs:186`, `:197` | `panic!("failed to download ...")` |

## 設計方針

1. curl に `--connect-timeout 30 --max-time 300 --retry 3 --retry-delay 5` を追加
2. SHA256 比較に定数時間比較を使用（`sha2` クレート導入または自前実装）
3. チェックサム値が `[0-9a-f]{64}` にマッチすることを検証
4. curl 失敗時は stderr をキャプチャしてエラーメッセージに含める

## 完了条件

- curl 呼び出しにタイムアウトとリトライが追加されていること
- SHA256 比較が定数時間で行われていること
- チェックサムファイルのフォーマット検証が追加されていること
- 既存の prebuilt / source-build 両経路でビルドが成功すること
